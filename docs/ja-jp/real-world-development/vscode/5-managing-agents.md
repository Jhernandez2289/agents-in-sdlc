エージェントモードの GitHub Copilot は、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、その作業をリアルタイムで確認できます。差分を確認して個々の変更を承認または取り消し、追加のプロンプトで作業を調整したり広げたりできます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して承認します。
- セッションの途中でエージェントに指示し、ハイコントラストモードとともにライトモードのトグルを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加します。新しい会話を始めるのではなく、既存のセッションに指示を追加します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集が順番に表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの実行状況を確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案したら、差分を確認します。
   - 変更を適用するには **Keep** を選択します。
   - 変更を取り消し、エージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、このセッションで変更されたファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止し、**Allow** の確認を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライトモードの追加を依頼する

ハイコントラストモードが実装されたら、同じ会話でライトモードのトグルを追加します。セッションを続けることで、エージェントはこれまでの作業、変更したコンポーネント、スタイルの方針、local storage の使い方を引き継げます。

1. Copilot Chat の入力欄に次のプロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を確認し、ライトモードの追加を提案する様子を確認します。
3. 新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合は、チャット入力欄の横にある **Stop** ボタンで停止してから、追加のメッセージで意図を伝えます。

> [!TIP]
> 進行中のセッションに追加のプロンプトを送ると、最初からやり直すよりもすばやく方向を調整できます。たとえば「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」「3 つ目のトグルは追加せず、既存の設定パネルにライトモードを統合してください」「両方のトグルにキーボードショートカットも追加してください」と依頼できます。

## 作業内容を確認する

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更したファイルをいくつか開き、差分を確認します。アクセシビリティカスタムエージェントのガイドラインに沿った ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持を確認します。
4. 内容に問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、方向付けました。ファイル編集を確認して承認または取り消し、コンテキストを保ったまま追加のプロンプトで作業を広げました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- 追加のプロンプトを使い、作業中のセッションを調整しました。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボ全体でローカルのカスタムエージェントが行った変更をレビューします。
